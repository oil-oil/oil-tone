# oil-tone

## 最重要的四件事

oil-tone 的首要目标是让文案**自然、易读、通顺、清楚**：读者能按自然语序读下去，轻松理解句子和段落的意思。事实有依据是不能突破的底线；结构、用词和删改都要服务于理解，不能为了短、正式或整齐而把话写得生硬。

1. **自然、易读、通顺。** 用符合语境的常用词和自然语序，保留完整、自然的表达节奏，不为压缩而写成生硬短句。中文里的“的”“了”等虚词只要承担语法、语气或关系作用，就应保留，不能默认当作赘词；是否留删，要结合意思和朗读效果判断，不机械增删。
2. **让读者跟得上。** 按读者此时已经知道的信息安排顺序。新对象让人跟不上时，只补理解它所缺的那一步；已经清楚的内容不重复解释。标题不能代替正文完成必要的交代。
3. **把关系讲完整。** 事实、操作、原因、结果和限制之间缺了一步时，先补这一步。一个句子通顺，不代表它能接上前一段；段落之间跳跃时，先调整信息顺序，不靠“接下来”“因此”等词掩盖。
4. **事实有依据。** 不编造经历、感受、用户反馈、数字和结果。把亲身体验、官方资料、推测和计划分开写；事实变化时核对当前材料。

## 写作与改写

- 先确认这篇内容要回答什么问题、材料支持哪些判断、读者需要先知道什么，再组织段落。每段承担一种主要作用，相邻段落应有读者能看出的关系。
- 按读者顺着上文自然产生的问题推进章节：**每个功能或概念只在最合适的一节完整讲透一次**，不在不同章节重复讲同一个问题，也不把“概念定义”和“真实场景”拆成前后两章重讲两遍；当文章同时包含专题讲解与菜单、命令或工具总览时，总览里只展开其他章节未覆盖的新项，已展开的功能只给一句索引指路，不按不同入口反复复述定义；节与节之间自然承接，不生硬硬切。
- 读者需要先认识某个产品、功能、术语或指标，才能理解后文时，在第一次用到它的地方用日常语言说明；读者已有上下文时直接往下讲。解释不要依赖另一个未经说明的词。
- 正文先讲到读者不打开链接也能理解。需要核对事实或进入产品、文档、仓库时，把链接放在对应说法旁边；链接不代替解释，也不集中堆在文末。
- 只要求润色时，保留原有事实、观点、数字、引用和必要格式。用户指出全文难懂或顺序不自然时，可以调整段落与章节，但不得借重排改变结论或补入无依据的细节。
- 整理访谈、口述或零散笔记底稿时，把当前底稿作为封闭事实源，做最小化整理：只清理口语水词、错别字和叙述顺序，不跨来源混入底稿未提及的细节，也不自行编造案例、数据或参数填空；信息有缺口时向作者追问，作者明确表示暂不下结论的地方如实保留边界。
- 标题说明真实对象、动作或判断；小标题精炼直接，不写冒号长句，不生硬堆砌缩写。标题中的所有权、时间、数量和结果都要有材料支持。
- 连续的解释和因果关系用自然段，自然段一般控制在 2–4 行；一段同时讲背景和做法且篇幅偏长时，在转折处拆段，避免密集文字墙。
- 并列项、步骤和查找信息再用列表或表格。**表格与列表不双写复述**：已经用对比表讲清的维度，表下不再用分点列表把表格内容逐条重说一遍，只补表格装不下的案例、边界或选型建议。单条列表超过 3 行时改拆短段或小节，多条共用的收尾句移出列表独立成段；整理口述或笔记要点时，把正反两面重复同一意思的并列项合并，确保每条是独立维度，不照搬原序号凑数。

## 语气与句子

- 写自己的做法和判断时用“我”；带读者看一般流程时可用“我们”；直接称呼读者群体时可用“大家”。不虚构共同经历，同一段内不频繁切换称呼。
- 写工具和产品时，优先呈现自己实际做过的操作、看到的结果、据此形成的判断和使用限制，并交代结论成立的前提环境（如使用场景、配置或任务强度）。不把有依据的个人判断改成中性的功能介绍。
- 句子要让人看清谁做了什么、作用于什么、发生了什么变化。上下文清楚时可以省略主语；读者需要回读猜测时应补清。
- “看、说、删、写、查、改、做、用”等常用动词，意思准确就直接使用。“的”“了”以及“在”“就”等虚词，只要能让语法、语气或关系表达得更自然、准确，就保留下来；不要为了压短句子或增加书面感而删掉，也不要为了显得口语而机械添加。判断时要连着上下文朗读，比较删改前后的自然程度和意思。
- 用平时真正会说的词称呼具体事物和动作：不用脱离日常表达的画廊策展腔或行业装腔词，也不为了显得口语而生造别扭的动词搭配；对比方案或解释机制时，直接讲清真实界面、目录或运行差别，不拿绕弯子的生活比喻替代，也不把工具或模型过度拟人化。
- 说明影响时写具体后果，不停在“有影响”“得到提升”一类泛指上；具体后果必须有材料依据，不能为了生动虚构场景。
- 不自我标榜（如“大白话”“通俗易懂”“掰开揉碎”），直接把事讲清楚；不虚构“经常有人问”等问答过渡；避免反复使用“顺手 / 用顺手”这类高频口癖（按语境改为“用好”“好用”“直接”或删掉）；不用“秒出”“绝杀”“护城河”“一家通吃”“100%”“永不”等夸张推销或绝对判断词，也不写审计免责套话。
- 不用没有信息量的行业背景、模糊归因、宣传口号、专栏点评式对仗金句、刻意制造反差的俏皮句、模板化转场和拔高结尾。删掉后不影响事实与关系的句子，可以直接删；确有转折或限定作用的表达不机械禁用。
- 按读者阅读目的控制技术细节：面向产品、方法或体验理解的内容，讲清它管什么事、怎么运转、解决什么问题即可，不写成 API 说明书，不堆砌不影响理解的函数签名、底层代码属性、命令行参数或内部脚本名。
- 中文按自然语法和标点书写；英文使用常见、直接的词。口播与社交内容保留自然的口语节奏；文档可以正式，但不要为了书面感删掉必要的虚词或连接表达。成稿要清理重复起句和无意义的语气词。

## 表达形式

- 文档、说明和正式通知以准确、易查找为先；口播与社交内容可以更接近日常说话，但同样要讲清对象和关系。
- 翻译外文内容时，译成自然通顺的母语表达，消除英文直译腔（例如把 `curation` 译为“筛选与整理”而非“策展”，把 `heuristics` 译为“实用判断原则”），忠实原标题核心意思，不自行追加塞满术语的长副标题，并保持原作者人称与行文干净。
- 已有成稿中的代码、专有名词、链接和引用来源按需保留；中文与英文、数字之间留一个半角空格。

## 完稿检查

1. 只读标题和各段首句：能否顺着它们讲出全文？新对象是否突然出现？各节是否重复讲了同一问题？发现跳跃或重复时先调整顺序或合并内容。
2. 连续读正文：每个判断是否有依据，原因和结果是否连得上，并列列表是否存在同义重复；不打开链接能否理解主要内容？
3. 按自然语速朗读：有没有不符合日常表达习惯的拗口句子？删掉“的”“了”等虚词后，语气、语法关系或意思有没有变生硬、变模糊？指代、动作对象、条件和状态是否清楚？修改后句子是否仍然完整？
4. 局部删改后做联动清查：删减、替换或收窄某段观点、范围或名词时，同步检查对应小标题、摘要、总结以及相邻示例、提示词和配图文案，防止前后口径不一致。
5. 长文或重要改稿做无上下文模拟读者试读：换干净上下文只读成稿，排查突然冒出的概念、理解卡点、超过 4 行的密集段落和同义重复；针对卡点只理顺句子、补半句铺垫或术语定义，严禁为迎合试读凭空编造原稿没有的案例或参数。
6. 文件成稿可运行本 Skill 的 `scripts/tone_lint.py` 查找值得复核的表达。脚本只提示少数套话、夸张词和空泛说法，无法判断文字是否自然、易读、通顺；逐条结合语境决定是否修改，最终以全文连读为准。
